Do not create session diaries or tool-execution logs. Omit empty/unchanged fields, chat narration, raw logs, temporary ports and one-time permission history. Do not invent evidence or persist secrets/customer data.
- **Keep status current:** `docs/PROJECT_STATUS.md` contains only current status, blockers, remaining completion conditions, concrete next actions and environment information useful to operations, with the verification date and scope. Keep local, staging and production distinct. Summarize the latest relevant check and link detailed acceptance evidence in the appropriate historical record; do not duplicate test tables or deployment snapshots across documents. Historical records do not replace current status.
- **Update, do not accumulate:** replace stale current-state notes for the same topic instead of appending snapshots. Retain dated historical evidence that still matters in its owning record and preserve approved decisions not yet implemented. Before removing temporary logs, confirm they are recoverable in Git history or no longer need preservation. Keep identifiers, fields, error codes, migration names, numeric limits, TTLs and configuration values when they define a contract, security rule, operating procedure or business decision. Record implemented versus integrated, verified versus pending explicitly; do not mark a phase/provider/deployment complete without its required evidence. Check changed links/anchors; avoid unrelated documentation rewrites.
- **Before an intentional stop or handoff:** within the authorized scope, replace the task's current item in PROJECT_STATUS, or the temporary handoff file explicitly requested by the owner, with the last verified state, unresolved issue and concrete next step if work remains. Otherwise keep the completed feature reference current. End the user report with one short sentence naming the documentation updated, or why no update was needed. ## Architecture and behavior

- React 18 + TypeScript/TSX, React Router 7, Vite 6, Tailwind CSS 4. Keep the pinned versions and npm lockfile consistent; do not migrate frameworks or add a second UI stack for routine changes.
- Routing lives in `src/app/router.tsx`. MainLayout exposes Home/Shop/Cart and `/orders/track`; `/cart` shows the product table/summary; `/checkout` is form → review → API confirmation, with memory-only CheckoutFlowProvider across both routes. `/admin/login` uses AuthLayout; AdminRoute wraps AdminLayout for dashboard/orders/stock/delivery-zones. `/admin` redirects to dashboard and `/admin/products` to stock. AppProviders composes I18nextProvider, real cookie AuthProvider, CatalogProvider, WishlistProvider and CartProvider; storefront wishlist is memory-only. Deferred customer auth/profile/orders/account wishlist/request and admin customers/settings/notifications source is retained and hidden; `VITE_ENABLE_CUSTOMER_AUTH` defaults false and a false customer-API-ready gate prevents fixture activation even when requested. See `docs/ARCHITECTURE.md` for ownership and rationale.
- Pages in `src/pages/` only compose feature views/hooks. State, business actions, services, types and fixtures live in `src/features/`; primitives and generic helpers live in `src/shared/`. Dependencies flow `pages → features → shared`; cross-feature imports use the feature's `index.ts`. App layouts keep their menu/routing state in app hooks.
- The Hono Worker in `worker/` is integrated with Vite by `@cloudflare/vite-plugin`. Phase 2 provides local D1 categories/products/product detail, delivery options and read-only checkout quotes, plus health and JSON API 404. Health checks Worker liveness only, not database readiness. Root `shared/` holds API constants/Zod schemas; delivery fees, slots and cutoff in `worker/config.ts` are initial assumptions for the owner to adjust.
- Orders use server pricing, UUID v4 idempotency and atomic stock subtraction/CHECK rollback. Quote is read-only and does not reserve stock. Reuse transitionOrder for exactly-once stock release and DELIVERED → PAID; no customer-cancel route exists. Keep the submitted statement budget ≤40 including failed batches/retries. Preserve fail-closed Turnstile; contract and invariants are in docs/reference/API_CONTRACT.md and docs/operations/BOT_PROTECTION.md.
- Admin authentication is one password plus HS256 JWT cookie lunara_admin (HttpOnly/SameSite=Strict/Path=/,12h,Secure on HTTPS). Keep SHA-256/timingSafeEqual, requireAdmin for every admin path except POST login, and same-origin Origin/JSON for writes. Owner sets ADMIN_PASSWORD≥24 random characters and distinct JWT_SECRET≥32; missing/invalid config fails closed. Keep parameterized queries and redacted allowlisted diagnostics; never raw SQL/binds/messages or credentials. Local workerd tests do not measure cloud CPU.
- Wrangler binds D1 as DB; keep Vite remoteBindings:false. Outputs are dist/client/ and dist/lunara/. Worker typing uses tsconfig.worker.json, worker/env.ts and worker-configuration.d.ts; run cf:typegen after binding changes. Applied migrations are immutable:0001 canonical base,0002 category image,0003 administrative catalog. Never apply deferred custom_requests SQL to MVP or run full seed to fill a narrow data gap. Deployment/migration state belongs in docs/PROJECT_STATUS.md.
- `AdminRoute` is wired for UI session loading/error/retry/redirect; server `requireAdmin` remains the authorization boundary. AuthProvider calls `/api/admin/me`, login and logout with same-origin cookies; do not persist credentials/JWT/session in browser storage. A 401 clears client admin state. Client-side role checks and `sessionStorage` do not provide production authorization.
- Keep short-lived UI state local. CatalogProvider loads categories/products once per reload/retry through Shop service; no fixture fallback. CartProvider owns cart lines across routes, keyed by variant ID. localStorage `lunara.cart.v1` stores only variantId/quantity, validated with Zod; quote owns current price/fee/totals. Checkout generates a UUID v4 for each submitted payload and keeps the same key on retry of that payload; order confirmation uses only API response. Never persist sender/recipient/order/phone/address or idempotency intent in browser storage. For ambiguous stock_delta write failures (NETWORK/TIMEOUT/BAD_RESPONSE/INTERNAL), clear the entered delta, lock that row and require a successful GET refresh before further edits; never retry a possibly-applied delta automatically. Backups in temp stay local/ignored. See docs/reference/FRONTEND_ENTITIES.md.
- The owner authorized D1 preview pricing in VND. Preserve EN default/fallback and customer-entered data; locale changes formatting only, not currency/timezone. Legacy PHP/settings source stays hidden. Delivery fees/cutoff/slots remain initial assumptions requiring owner decisions before opening sales.

## Design and reuse

- **Current brand source of truth:** `src/shared/theme/themes.ts`, `src/shared/theme/theme-store.ts`, and `src/styles/brand.css`; `docs/ui-ux/DESIGN_SYSTEM.md` owns design intent. There are 22 **light** themes. The default **Original** is the owner-approved Monochrome/pink palette (stable ID `monochrome`); the former green/white-mist Original is selectable as **Green Mist** (stable ID `original`). Preserve stored IDs and palette values when changing display names. `rose`, `cream` and `blush` are compatibility token names, not literal colors; use semantic roles instead of component HEX values.
- **Role-based color mapping:** use existing Lunarra semantic CSS variables / Tailwind `lunara-*` utilities for backgrounds, cards, text, muted text, borders, CTA/hover, focus, links and states. Define palette HEX values and semantic mappings in the theme layer. Keep the generic shadcn `theme.css` palette distinct from the brand. Do not branch JSX on theme IDs to choose colors.
- **Visual hierarchy target:** keep the established light, editorial flower-storefront design (photography, generous neutral surfaces, measured spacing). For creative themes use primary color for major CTA and selected navigation; secondary/tertiary are restrained **local** decorative accents, not mandatory full-width utility-bar/Hero/Journey fills or alternating bright backgrounds. Preserve the existing layout unless the owner asks for redesign.
- **Theme changes:** current creative mapping and interaction are documented in `docs/ui-ux/DESIGN_SYSTEM.md`; inspect source before changing them. Update semantic mappings and visual tests together with an approved change. Preserve the behavior/appearance of the 16 pre-creative themes unless separately authorized.
- **Typography by locale:** use `font-display` headings/logo and `font-body` body/forms. EN = Fraunces (500 / 500 Italic) + Inter; VI = Lora (Regular 400, including Italic) + Be Vietnam Pro. `html[lang='vi']` and font aliases propagate locale through portal UI. Fonts are linked in `index.html`. Do not override fonts per component without a design requirement.
- **Components:** reuse `src/shared/ui/` Radix/shadcn wrappers, `cn` from `src/shared/lib/utils.ts`, feature-level ProductCard/ProductGrid/FilterBar, `ImageWithFallback`, formats and Lucide icons. Use the existing component inventory before creating new primitives or duplicating feature state. CSS holds global tokens/focus behavior; Tailwind handles ordinary presentation styles.
- **Interaction and accessibility:** support EN/VI, responsive layout, real loading/error/empty/success states, labels, icon-button accessible names, image alt, keyboard access, reduced motion. Distinguish `hover`, checked/selected, active route and keyboard `focus-visible`; never suppress keyboard focus globally. Aim WCAG AA: >=4.5:1 normal text, >=3:1 large text and applicable control/focus indicators. Test actual foreground/background/hover pairs (including white-text CTA) for all affected themes.
- **Admin and states:** semantic success/warning/error retain their meaning. Admin sidebar/background are separate from storefront themes; specific admin active/header tokens may be theme-aware. Do not describe all admin tokens as immutable or all brand tokens as pink.
- **Design skill:** use `.agents/skills/lunarra-design/SKILL.md` for explicitly invoked external-design adaptations/visual audits; its `agents/openai.yaml` currently disables implicit invocation. Routine UI work uses `.agents/skills/lunara-flower-shop/SKILL.md`.

## Tooling, security, and delivery

- Use `npm ci` for reproducible installs. `.npmrc` uses the official HTTPS registry and `ignore-scripts=true`; keep it. Run authorized build/dev commands explicitly. Never resolve install issues by globally enabling dependency scripts.
- Dev and preview bind to `127.0.0.1`; preserve this unless external access is explicitly requested. Preserve the Vite React/Tailwind plugins, `@` alias, and `figma:asset/` resolver.
- Keep `.dev.vars` and `.wrangler/` local; only demo placeholders belong in `.dev.vars.example`. Run `npm run smoke` against the running local server after Worker changes: catalog checks use that server, while Phase 3–4 writes run through a separate loopback HTTP server with isolated workerd D1 `persist:false`, `remoteBindings:false`, demo envFiles and synthetic admin secrets. Preserve the local-only guard, secret redaction and persisted snapshot check; do not use ambient real secrets for tests. Smoke deployment mode requires explicit `--base-url` HTTPS origin and defaults to reads; writes also require matching `--confirm-origin`, explicit variant ID, exclusive test window, and credentials through hidden stdin. Mark all test orders SMOKE, never auto-retry ambiguous stock writes, and follow docs/operations/OPERATIONS.md for reconciliation/cleanup. D1 commands must use `--local` unless remote work is explicitly requested; reset removes local D1 state. Phase 1 seed is sample data. Run `npm run db:verify` after database changes; its destructive cases use isolated local D1 and leave the seeded database untouched. After the Phase1 schema agreement, preserve the applied base DDL; schema extensions need a demonstrated test failure or an explicitly owner-requested feature, a documented reason, and a new migration after remote application.
- Never put real secrets, payment credentials, customer data, or real passwords in source, `VITE_*` variables, screenshots, or docs. Only reviewed instruction files inside `.agents/` may enter Git; local `.codex/config.toml` and `.codegraph/` remain ignored.
- `.gitignore` is a default-deny allowlist. For a new shared file, add its exact path and any required parent-directory exceptions after reviewing its contents. Never use `git add -f` to bypass the policy.
- CodeGraph is a local navigation aid, not a security scanner. It must not index dependency/build/audit/secret folders; exclusions are in root `codegraph.json`.
- Use official OpenAI Docs MCP for Codex/OpenAI questions when available; otherwise read official OpenAI documentation. Do not inject unrelated OpenAI integration into this storefront.
- For runtime/style/build changes, run `npm run typecheck`, `npm run check:architecture`, `npm test`, `npm run build`, and verify affected flows. For dependency changes, also run `npm audit`. `npm run check:ui -- http://127.0.0.1:4173` checks a running preview with Edge headless on Windows. Vite build does not replace typecheck; no ESLint script is configured.
- Test behavior that can regress; documentation-only changes need link/path review, not a new test framework. Sync CodeGraph after code changes.
- Before commit/push, review `git status`, file inclusion, and `git diff --check`. Commit/push/deploy only when included in the current request or standing authorization; a previous one-time push is not blanket authorization for future pushes.
