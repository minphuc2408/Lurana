Omit empty/unchanged fields, chat narration, raw logs, temporary ports and one-time permission history. Do not invent evidence or persist secrets/customer data.

Record local versus remote, implemented versus integrated, verified versus pending explicitly. Do not mark a phase/provider/deployment complete without its required evidence. Check changed links/anchors; avoid unrelated documentation rewrites.
- **Before an intentional stop or handoff:** if work remains, leave a short current item in PROJECT_STATUS with the last verified state, unresolved issue and concrete next step, replacing the prior item for that task. Otherwise keep the completed feature reference current; do not append a session diary. End the user report with one short sentence naming the documentation updated, or why no update was needed. This policy does not authorize commit/push/deploy or remote writes.

## Architecture and behavior

- React 18 + TypeScript/TSX, React Router 7, Vite 6, Tailwind CSS 4. Keep the pinned versions and npm lockfile consistent; do not migrate frameworks or add a second UI stack for routine changes.
- Routing lives in `src/app/router.tsx`. MainLayout exposes Home/Shop/Cart and `/orders/track`; `/cart` shows the product table/summary; `/checkout` is form → review → API confirmation, with memory-only CheckoutFlowProvider across both routes. `/admin/login` uses AuthLayout; AdminRoute wraps AdminLayout for dashboard/orders/stock/delivery-zones. `/admin` redirects to dashboard and `/admin/products` to stock. AppProviders composes I18nextProvider, real cookie AuthProvider, CatalogProvider and CartProvider. Deferred customer auth/profile/orders/wishlist/request and admin customers/settings/notifications source is retained and hidden; `VITE_ENABLE_CUSTOMER_AUTH` defaults false and a false customer-API-ready gate prevents fixture activation even when requested.
- Pages in `src/pages/` only compose feature views/hooks. State, business actions, services, types and fixtures live in `src/features/`; primitives and generic helpers live in `src/shared/`. Dependencies flow `pages → features → shared`; cross-feature imports use the feature's `index.ts`. App layouts keep their menu/routing state in app hooks.
- The Hono Worker in `worker/` is integrated with Vite by `@cloudflare/vite-plugin`. Phase 2 provides local D1 categories/products/product detail, delivery options and read-only checkout quotes, plus health and JSON API 404. Health checks Worker liveness only, not database readiness. Root `shared/` holds API constants/Zod schemas; delivery fees, slots and cutoff in `worker/config.ts` are initial assumptions for the owner to adjust.
- Orders use server pricing, UUID v4 idempotency and atomic stock subtraction/CHECK rollback. Quote is read-only and does not reserve stock. Reuse transitionOrder for exactly-once stock release and DELIVERED → PAID; no customer-cancel route exists. Keep the submitted statement budget ≤40 including failed batches/retries. Preserve fail-closed Turnstile; contract and invariants are in docs/pipeline/API_CONTRACT.md and docs/BOT_PROTECTION.md.
- Admin authentication is one password plus HS256 JWT cookie lunara_admin (HttpOnly/SameSite=Strict/Path=/,12h,Secure on HTTPS). Keep SHA-256/timingSafeEqual, requireAdmin for every admin path except POST login, and same-origin Origin/JSON for writes. Owner sets ADMIN_PASSWORD≥24 random characters and distinct JWT_SECRET≥32; missing/invalid config fails closed. Keep parameterized queries and redacted allowlisted diagnostics; never raw SQL/binds/messages or credentials. Local workerd tests do not measure cloud CPU.
- Wrangler binds D1 as DB; keep Vite remoteBindings:false. Outputs are dist/client/ and dist/lunara/. Worker typing uses tsconfig.worker.json, worker/env.ts and worker-configuration.d.ts; run cf:typegen after binding changes. Applied migrations are immutable:0001 canonical base,0002 category image,0003 administrative catalog. Never apply deferred custom_requests SQL to MVP or run full seed to fill a narrow data gap. Deployment/migration state belongs in docs/PROJECT_STATUS.md.
- `AdminRoute` is wired for UI session loading/error/retry/redirect; server `requireAdmin` remains the authorization boundary. AuthProvider calls `/api/admin/me`, login and logout with same-origin cookies; do not persist credentials/JWT/session in browser storage. A 401 clears client admin state. Client-side role checks and `sessionStorage` do not provide production authorization.
- Keep short-lived UI state local. CatalogProvider loads categories/products once per reload/retry through Shop service; no fixture fallback. CartProvider owns cart lines across routes, keyed by variant ID. localStorage `lunara.cart.v1` stores only variantId/quantity, validated with Zod; quote owns current price/fee/totals. Checkout generates a UUID v4 for each submitted payload and keeps the same key on retry of that payload; order confirmation uses only API response. Never persist sender/recipient/order/phone/address or idempotency intent in browser storage. For ambiguous stock_delta write failures (NETWORK/TIMEOUT/BAD_RESPONSE/INTERNAL), clear the entered delta, lock that row and require a successful GET refresh before further edits; never retry a possibly-applied delta automatically. Backups in temp stay local/ignored. See docs/pipeline/FE_AUDIT.md.
- The owner authorized D1 preview pricing in VND. Preserve EN default/fallback and customer-entered data; locale changes formatting only, not currency/timezone. Legacy PHP/settings source stays hidden. Delivery fees/cutoff/slots remain initial assumptions requiring owner decisions before opening sales.

## Design and reuse

- Use the existing cream/rose floral direction: rose `#C17B8A`, cream `#FDF6F0`, ink `#3D2228`, body text `#6B4C55`, blush `#F9EDE9`, border `#F0DDD5`.
- New UI uses `src/styles/brand.css` tokens or its `lunara-*` Tailwind utilities. Use `font-display` for headings/logo and `font-body` for body/forms: EN uses Fraunces 500 (500 Italic emphasis, automatic optical sizing)/Inter; VI uses Lora Regular 400 headings/logo (including italic) and Be Vietnam Pro body/forms; html and font-sans/font-serif inherit locale tokens through `html[lang='vi']`. Keep global shadcn tokens separate until a requested migration is scoped.
- The original rose with white text fails normal-text contrast. For new white-text CTAs, use `lunara-rose-strong` (`#9D586B`); preserve focus visibility and test actual foreground/background pairs. Do not use pale muted/status colors for essential small text.
- Check `src/shared/ui/` before creating a primitive. Retained primitives are `button`, `input`, `dialog`, `dropdown` and `combobox`; unused modules were removed. `cn` lives in `src/shared/lib/utils.ts`, `useIsMobile` in `src/shared/hooks/use-mobile.ts`. Customize retained primitives for Lunara.
- Use Tailwind directly in presentation JSX; CSS holds global theme, brand tokens and focus styling. Reuse `features/shop` ProductCard/ProductGrid/FilterBar, feature sections, `ImageWithFallback`, and `shared/lib/format.ts`. Keep changes within the requested feature; do not reorganize unrelated modules for routine edits.
- Keep rounded cards, pill CTAs, restrained shadows, flower photography, and Lucide icons. Preserve responsive navigation, usable forms, loading/error/empty/success states, accessible labels, and keyboard access for changed flows.

- Use `npm ci` for reproducible installs. `.npmrc` uses the official HTTPS registry and `ignore-scripts=true`; keep it. Run authorized build/dev commands explicitly. Never resolve install issues by globally enabling dependency scripts.

Preserve the local-only guard, secret redaction and persisted snapshot check; do not use ambient real secrets for tests. Smoke deployment mode requires explicit `--base-url` HTTPS origin and defaults to reads; writes also require matching `--confirm-origin`, explicit variant ID, exclusive test window, and credentials through hidden stdin. Run `npm run db:verify` after database changes; its destructive cases use isolated local D1 and leave the seeded database untouched. After the Phase1 schema agreement, preserve the applied base DDL; schema extensions need a demonstrated test failure or an explicitly owner-requested feature, a documented reason, and a new migration after remote application.

- CodeGraph is a local navigation aid, not a security scanner. It must not index dependency/build/audit/secret folders; exclusions are in root `codegraph.json`.
- Use official OpenAI Docs MCP for Codex/OpenAI questions when available; otherwise read official OpenAI documentation. Do not inject unrelated OpenAI integration into this storefront.
- For runtime/style/build changes, run `npm run typecheck`, `npm run check:architecture`, `npm test`, `npm run build`, and verify affected flows. For dependency changes, also run `npm audit`. `npm run check:ui -- http://127.0.0.1:4173` checks a running preview with Edge headless on Windows. Vite build does not replace typecheck; no ESLint script is configured.
- Test behavior that can regress; documentation-only changes need link/path review, not a new test framework. Sync CodeGraph after code changes.
- Before commit/push, review `git status`, file inclusion, and `git diff --check`. Commit/push/deploy only when included in the current request or standing authorization; a previous one-time push is not blanket authorization for future pushes.
